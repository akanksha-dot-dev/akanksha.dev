## Intent

First-time visitors (technical recruiters and engineering managers) should immediately see the cyber-physical laboratory in action without needing to click buttons first. An automated preview runs a simulated RAG pipeline trace, streaming steps and output to prove technical capability, but seamlessly yields to manual control the moment the visitor touches any control.

## Key Files

- `src/components/AiSandbox.astro` (lines 1-482)

## Specification

1. In `src/components/AiSandbox.astro`, add an "Auto-Demo" status badge in the header next to the tab switch or header subtitle (e.g., `<span id="auto-demo-badge" class="hidden text-[0.65rem] font-mono px-2 py-0.5 rounded-full border border-teal-500/30 bg-teal-500/10 text-teal-300 items-center gap-1.5"><span class="w-1.5 h-1.5 rounded-full bg-teal-400 animate-pulse"></span> Auto-Demo</span>`).
2. Add an `IntersectionObserver` that observes `#ai-sandbox-container`.
3. When the container is at least 30% visible and the user has not yet interacted with the sandbox, schedule an automated execution of the default query (`revenue`) after 1000ms.
4. If the user clicks `btn-run-rag`, `btn-run-agent`, `btn-rag-tab`, `btn-agent-tab`, `rag-query-select`, `agent-task-select`, `toggle-router`, or `toggle-guardrails`, immediately cancel any pending auto-demo timeout, hide the auto-demo badge, and mark `userInteracted = true`.
5. Support Astro page navigation (`astro:page-load`) by properly cleaning up timers and observer instances.

## Constraints

- Do NOT make external network or API calls. All data must remain local and deterministic.
- Do NOT disrupt manual user interactions or block user clicks.
- Do NOT touch files outside `files_targeted`.
